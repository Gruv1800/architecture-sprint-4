# Выбор и настройка мониторинга в системе

## Мотивация

Добавление мониторинга в систему "Александрит" позволит сделать её более стабильной, производительной и безопасной. Основные преимущества данного действия:

- Снижение времени простоя во время инцидентов за счет быстрого обнаружения неисправности (или симптомов);
- Предоставление информации для оптимизации и улучшения производительности за счет анализа метрик;
- Предотвращение инцидентов за счет настройки уведомлений (алертов) на аномальные показатели метрик;
- Автоматизация реагирование на инциденты\аномалии (перезапуск сервисов, автоскейлинг и т.п);
- Отслеживание ключевых метрик, влияющих на пользовательский опыт (время отклика системы или частота ошибок) и дальнейшее устранение проблем, повышающее удовлетворённость пользователей.

## Выбор подхода к мониторингу

**Мониторинг API:** для мониторинга Shop API, MES API и CRM API выбираю RED подход, т.к. данный подход позволяет оценить работу сервисов с точки зрения пользовательского опыта и направлен на удовлетворение конечных потребителей (уменьшение времени ответа и кол-ва ошибок). Так же в рамках данного подхода будет реализован мониторинг производительности БД и очереди сообщений.
**Мониторинг MES:** т.к. данный компонент системы занимается сложными вычислениями и предъявляет повышенные требования к ресурсам, предлагаю применить подход USE, для более качественного мониторинга hardware и middleware составляющей системы.    

## Метрики для отслеживания

- Number of dead-letter-exchange letters in RabbitMQ - подойдет для мониторинга аномалий при обработке взятии в обработку новых заказов;
- Number of requests (RPS) for ***(all) APIs - для понимания общей нагрузки на API. Полезно использовать лейбл path (path=/some/url) для выявления самых "горячих" точек API
- CPU % for MES API - для отслеживания утилизации CPU, поскольку MES требователен к hardware ресурсам
- Memory Utilisation for MES API - для отслеживания утилизации RAM, поскольку MES требователен к hardware ресурсам
- Number of connections for shop db instance - может "подсветить" неоптимальную работу с БД (долгие запросы держат коннекшен к БД)
- Number of connections for MES db instance - аналогично предыдущему
- Response time (latency) for shop API - время ответа на запросы к shop API. Напрямую влияет на пользовательский опыт. Полезно использовать лейбл path (path=/some/url) для выявления самых "горячих" точек API
- Response time (latency) for MES API - аналогично предыдущему
- Size of S3 storage - данный о заполненности S3 хранилища. Позволит реагировать на критический % заполнений и заблаговременно принять меры по увеличению размера хранилища (или очистки исторических данных) 
- Size of shop db instance - полезно понимать текущее состояние (объем) и динамику роста БД с заказами, а также принятие мер по предотвращению полного заполнения дискового пространства
- Size of MES db instance - аналогично предыдущему
- Number of HTTP 200 for ***(all) APIs - количество\процент успешных запросов
- Number of HTTP 500 for ***(all) APIs - количество\процент запросов обработанных с ошибкой

## План действий

- Развернуть систему мониторинга Prometheus
- Добавить агенты и экспортеры в компоненты системы "Александрит" для сбора и отправки метрик в Prometheus
- Определить набор метрик для выгрузки в каждом компоненте
- Развернуть Grafana
- Настроить дашборды для визуализации данных на основе метрик
- Настроить алерты
